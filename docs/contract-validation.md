# Allocation binding, minimum witnesses, and executable contracts

## Basis and scope

These checks use the supplied TOS manuscript and artifact. The raw observations
in `results/targeted/binding-minimum-format-before.json` were executed before
editing the implementation, not inferred from previous review reports. Current
observations are generated by `scripts/check_targeted.py` and the assertions in
`tests/test_targeted_contracts.py`. Fixtures in `tests/targeted_cases.py` are
explicit and do not use the workload generator. The edits address these
contracts only; they do not introduce a new storage system, workload, proof
assistant, or performance comparison.

## Complete-trace binding

The two-event fixture has `operations=[delete(x)]`, root 0 at prefix 1 with an
empty namespace and `manifest_ref=(slot0,gen1,SHA256('{}'),2)`, then data 1 writing
those bytes with chunk role. The acknowledgement has `issued=2,prefix=1` and
anchors `[0,1]`. Before repair both parsers admitted it. The fixed-candidate
fallback analyzer returned safe, while the per-cut byte oracle found `[0,1]`
unsafe: recovery skipped the chunk-role manifest, returned prefix 0 and violated
the acknowledgement. All four cuts and their recovered outcomes are retained.

Late chunk fixtures reproduced two further mismatches: a matching allocation
with manifest rather than chunk role, and valid chunk allocations concatenating
to `b'b'` although the ghost object is `b'a'`. The old static fallback test
returned safe; full byte recovery or the oracle's expected-byte comparison did
not. A noncanonical manifest-reference fixture was **already rejected** before
repair; it is a negative control, not a newly discovered acceptance defect.

Both parsers now build the full allocation index and then perform a second
binding pass for every root. Present manifests require manifest role and exact
canonical namespace bytes. Present object allocations require chunk role, even
when another reference is missing. Completely bound objects must reconstruct
exactly the ghost bytes. The ghost namespace still must match the operation
prefix, and the canonical manifest reference remains independently checked.

Correctly bound late manifests and chunks stay admitted. With the specified
anchors their fallback acknowledgement checks agree with the byte oracle and
are safe. Strict recovery still rejects their publication order. References
whose matching allocation never exists also remain admitted; both exact
fallback and byte oracle classify the missing-manifest and missing-chunk
fixtures unsafe with matching minimum cuts. No future-to-past dependency or
implicit allocation-before-root admission restriction has been introduced.

The directed malformed late-binding fixtures already failed P under the old
strict analyzer because a root could not force its future allocation. These
observations identify a parser precondition/fallback-encoding mismatch; they
are not evidence that the strict P/D/A theorem is false on correctly admitted
traces.

## Multiple acknowledgements and budgeted minimality

With no roots, one independent event 0, and two acknowledgements both at
`issued=1,prefix=1` but anchored first at `[0]` and then at `[]`, the old code
returned `[0]`; the byte oracle's minimum is `[]`. Reordering the acknowledgements
changed that old result. A second fixture showed that a no-candidate branch
could also discard an earlier, better incumbent from a normal candidate search.

A no-candidate-root acknowledgement now contributes its anchor closure and
continues. Every feasible candidate across every acknowledgement competes with
the incumbent by `(cardinality, sorted-event-ID tuple)`. Both fixtures return
`[]` in either acknowledgement order. The budget applies across enumerated
products; zero-budget mixed cases return `unknown`, `safe=null`, and
`minimum_bad_cut=null`. When an earlier violation is retained as `bad_cut`, it is
explicitly not advertised as minimum. The one-acknowledgement proof is unchanged;
its application to several acknowledgements requires this final minimization.

## Controlled format failures and CLI

Before repair `role=[]` and `role={}` leaked `TypeError` in both parsers. Image
role and kind lists/dictionaries also leaked from recovery. Null role values and
trace kind values already produced controlled errors; these controls are
recorded without claiming new defects for them. String-type checks now precede
set membership. Direct APIs raise their existing controlled parser error family
or return a malformed recovery result. Verification exposes a trace-format
subclass of `VerificationError` so its CLI can distinguish malformed traces from
rejected certificates. No blanket catch of unrelated `TypeError` was added.

The CLI has explicit JSON statuses. Malformed input and unknown both exit 2,
but have distinct status values; unsafe exits 1 and safe exits 0. Certificate
acceptance/rejection is distinct from trace safety. A well-formed but
unreconstructible image is unsafe; structural image failure is malformed.
Subprocess tests check stdout JSON, return status and absence of traceback or
TypeError for lists, dictionaries and null in both fields.

## Canonical certificates

The contract chooses exactly `F(w)` for a retirement row, the maximum root in
an anchor closure for a positive acknowledgement, and `-1` for prefix zero.
Arrays have exact traversal and row equality; the consumer does not accept an
arbitrary satisfying witness. The safe seven-event fixture has both roots 3
and 5 sufficient for retirement and the positive acknowledgement. The producer
uses 5; the consumer accepts it and rejects either replacement with 3. Section
3.3, the proof of Theorem 4.3, and `formats.md` now state the same contract.

## Generator, byte costs, and solver

Section 6.1 now describes the implemented in-memory specification-state trace
generator. It appends events and later passes selected cuts to offline
materialization and recovery. No online medium application or medium-backed
read path is claimed. The small cost regression also executes generation,
admission, materialization and recovery as an offline chain.

The cost formula is unchanged: compact canonical JSON descriptor length plus
one separator byte, plus raw payload length for data records. Data descriptors
contain kind, slot, generation, digest, length and role; root descriptors contain
kind, prefix and manifest reference; free descriptors contain kind, slot and
generation. `id`, `deps`, `data_hex`, root ghost fields, acknowledgements and
trace/image envelopes are excluded. Section 6.4 and `formats.md` make this
explicit. There is no claim that these values are full wire-JSON lengths.

There is no solver CLI. Experiment scripts call the Z3 C-library wrapper.
Missing/unusable libraries raise `SolverUnavailable`; capability probing returns
false and full mode refuses to launch. Core mode records omitted SMT queries.
An actual Z3 unknown response is separate. Mocked unit tests verify unavailable-
library and preflight/omission control paths; these mocks are not presented as
new solver experiments or actual unavailable-library campaign runs.

## Measurement and manuscript preservation

The 75-method current suite includes 20 added directed/contract methods relative
to the supplied 55-method suite. The full seven-stage campaign was actually
rerun on repaired code in a clean separate tree, followed by aggregation and the
POSIX illustration. All 17 primary result files matched retained logical values
when only declared host fields were normalized. Inputs, implementation, scripts
and tests were byte-identical across the compared trees. The primary unit-test
record and derived test counts were updated to the fresh run. Other primary
measurement records and `paper/measurements.tex` were retained, not replaced by
the new timings. See `reproduction-check.json` and `reproduction.md`.

All existing table bodies and the three TikZ/PGFPlots figure environments remain
byte-identical to the supplied manuscript. Publisher class, bibliography style,
bibliography and the author JSON are unchanged. Only targeted narrative,
contract/proof wording and supporting regression explanation were edited.
The four null author slots remain metadata to be resolved by the responsible
author, who determines real author count and information. The builder no longer
forces exactly six people, but the supplied slots and PDF placeholders remain
synchronized until that decision. Missing metadata or approval is not classified
as a scientific defect, and no identity or consent is invented. Scope limitations
and the substantive AI-use disclosure are retained.
